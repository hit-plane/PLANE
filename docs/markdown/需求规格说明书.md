## 1. 项目概述与范围边界

### 1.1 项目概述

飞机大战是一款 2D 竖版单人飞行射击游戏：玩家操控战机在战场内移动，战机自动向上连续发射子弹，击毁从顶部不断生成并下压的敌机以获得分数，同时躲避敌机与敌弹；玩家拥有血量，血量归零则本局结束。击毁敌机可概率掉落道具，关卡随得分提升而加大敌机密度与速度。本说明书定义本期（Java 实训）开发范围内的功能与非功能需求，只描述"系统做什么、做到什么标准"，不描述界面布局与代码实现。

### 1.2 范围边界

**本期做（P0/P1）**：玩家移动与自动射击、四类敌机的生成与行为、碰撞检测与击毁、计分、玩家血量与受击、游戏结束、道具、难度关卡、暂停、最高分持久化。

**明确不做（P2，来源：客户材料 + Q5/Q8）**：联机对战与网战 PK、双人同机、移动平台、二段跳、地形障碍、天气影响弹道、友军 NPC、零件组装、武器合成、Boss 及多阶段 Boss、关卡编辑器、AI 自动玩。上述内容列入二期扩展，本期不投入开发。

## 2. 术语表

| 术语 | 定义 |
| -- | -- |
| 战场 | 竖版矩形游戏区域，全文统一称"战场"，不使用"棋盘/网格/场地" |
| 玩家战机 | 玩家操控的己方飞机，初始位于战场底部中央 |
| 敌机 | 从战场顶部生成、向下运动的敌方飞机，分普通/横移/射击/自爆四类 |
| 玩家子弹 | 战机自动发射、向上飞行、用于击毁敌机的子弹 |
| 敌弹 | 射击类敌机发射、向下飞行、命中玩家会扣血的子弹 |
| 碰撞盒 | 用于判定两个实体是否接触的矩形区域 |
| 击毁 | 敌机累计受伤达到其血量后被销毁的过程 |
| 关卡 | 按累计得分划分的难度阶段，每 1000 分为 1 关 |
| 道具 | 击毁敌机按概率掉落、玩家战机接触后获得增益的物体 |
| 无敌时间 | 玩家受击后短暂免疫伤害的时间窗口，本期为 1 秒 |
| 最高分 | 历史所有对局中得分最高的一局对应分数，关机后保留 |

## 4. 功能需求清单（F01–F16）

> 优先级：P0 = 核心闭环必备（砍掉则游戏无法完整进行一局）；P1 = 重要增强；P2 = 本期不做/可选扩展。
> 出处：客户原文 ✅ / QA 澄清 Q# / 隐含补充 💤 / AI 边界补充 A#。
> **P0（F01–F09）覆盖完整流程：能开始 → 能进行 → 能结束。**

| 编号 | 功能 | 优先级 | 一句话说明 | 出处 |
| -- | -- | -- | -- | -- |
| F01 | 开始游戏 | P0 | 从主菜单进入一局：分数归零、玩家血量回满、清空场上敌机/子弹/道具 | 客户原文 ✅ |
| F02 | 玩家战机移动 | P0 | 方向键/WASD 控制上下左右移动；战机可在整个战场内移动但不得移出窗口边界 | 客户原文 ✅ + Q4 |
| F03 | 玩家自动射击 | P0 | 进入一局后按固定间隔自动向上发射子弹，不做手动发射；子弹飞出顶部即销毁 | 客户原文 ✅ + Q1 |
| F04 | 敌机生成 | P0 | 系统定时器从战场顶部随机横坐标生成敌机，生成间隔随关卡缩短 | 客户原文 ✅ |
| F05 | 敌机移动、攻击与离场 | P0 | 普通敌机直冲、横移敌机左右摆动、射击敌机下压并发射敌弹、自爆敌机高速下压；敌机飞出底部直接销毁不扣分 | 客户原文 ✅ + Q7 |
| F06 | 碰撞检测与击毁 | P0 | 玩家子弹与敌机重叠则敌机扣血、子弹销毁；敌机血量归零即击毁；一帧内多对碰撞全部结算，不遗漏 | 客户原文 ✅ + A1 |

| F09 | 游戏结束判定 | P0 | 玩家血量归零立即结束，冻结全部运动，显示本局得分并更新最高分 | 客户原文 ✅ + Q2 |

## 5. 用户故事（每个 P0 一段）

- **F01**：作为玩家，我希望从主菜单一键开始一局新游戏，以便每次都能从满血、零分的干净状态开始挑战。
- **F02**：作为玩家，我希望用键盘自由控制战机在战场内移动，以便躲避来袭的敌机和敌弹、占据有利射击位置。
- **F03**：作为玩家，我希望战机进入战斗后自动连续发射子弹，以便我专注于走位和躲避，不必分心反复按键开火。
- **F04**：作为玩家，我希望敌机不断从顶部随机位置出现，以便每一局面对的敌机排布都不同，保持挑战性。
- **F05**：作为玩家，我希望不同敌机有不同的下压和攻击方式，以便我能根据敌机类型判断威胁优先级、采取不同规避策略。
- **F06**：作为玩家，我希望子弹命中敌机后能逐步将其击毁，以便我的操作能得到明确、即时的反馈。
- **F07**：作为玩家，我希望战机有血量且受击后有短暂无敌时间，以便一次小失误不会被连续命中直接结束，操作更有容错。
- **F08**：作为玩家，我希望击毁不同敌机得到对应分数，以便通过分数量化我的战斗成果并追求更高纪录。
- **F09**：作为玩家，我希望血量耗尽时游戏明确结束并展示本局得分，以便我清楚本局结果并决定是否再来一局。

### 7.2 活动图 2：单帧碰撞与击毁结算

![活动图2](activity-collision.png)

| 节点 | 说明 |
| -- | -- |
| 收集本帧全部碰撞对 | 一次性找出所有"子弹–敌机"重叠对 |
| ◇ 存在碰撞对？ | 无则直接跳到玩家受击判定 |
| 取出下一对碰撞并结算 | 敌机扣血、销毁子弹 |

## 8. 验收标准（Given–When–Then，每条 P0 至少 1 条）

> 每条 Then 均可转为 Day06 的一条测试用例：Given 搭建前置数据，When 调用对应更新/结算方法，Then 用断言判定结果。全表无模糊词。

| 编号 | Given（前置状态） | When（操作/事件） | Then（可判定结果） |
| -- | -- | -- | -- |
| GWT-01（F01） | 处于主菜单、尚未开始，历史最高分为 0 | 玩家选择"开始游戏" | 分数=0、玩家血量=100；场上敌机/敌弹/玩家子弹/道具数量均为 0；战机位于战场底部中央 |
| GWT-02（F02） | 一局进行中，战机左边缘已与战场左边界重合 | 玩家持续按向左键 | 战机横坐标不再减小，战机碰撞盒始终完全位于战场边界内 |
| GWT-03（F03） | 一局进行中，当前无玩家子弹 | 经过一个射击间隔（300ms） | 战机机头位置生成 1 颗玩家子弹并沿竖直方向向上移动；该子弹顶部移出战场边界后被销毁，场上子弹数减 1 |
| GWT-04（F04） | 一局进行中、当前为第 1 关，场上敌机数为 n | 敌机生成定时器触发一次 | 战场顶部区间内某随机横坐标生成 1 架敌机，场上敌机数变为 n+1，其初始纵坐标位于顶部边界外 |
| GWT-05a（F05） | 1 架普通敌机底边已移出战场下边界 | 下一帧更新执行 | 该敌机被销毁，玩家分数保持不变 |
| GWT-05b（F05） | 场上存在 1 架射击敌机且距其上次发射已达射击间隔 | 本帧更新执行 | 该敌机位置生成 1 颗敌弹并沿竖直方向向下移动 |
| GWT-06（F06） | 1 架血量为 1 的普通敌机与 1 颗玩家子弹碰撞盒重叠 | 本帧碰撞结算执行 | 该敌机与该子弹均被销毁，玩家分数增加 100 |
| GWT-07a（F07） | 玩家血量 100、未处于无敌状态 | 1 颗敌弹命中玩家 | 玩家血量变为 90，并进入持续 1 秒的无敌状态 |
| GWT-07b（F07） | 玩家处于 1 秒无敌状态、血量 90 | 无敌期间再次被敌弹命中 | 玩家血量保持 90 不变，本次命中不造成伤害 |
| GWT-07c（F07） | 玩家血量 100，与 1 架敌机碰撞盒重叠 | 本帧碰撞结算执行 | 玩家血量变为 80，该敌机被销毁 |
| GWT-08（F08） | 玩家当前分数为 0 | 依次击毁普通、横移、射击敌机各 1 架 | 分数依次增加 100、150、200，最终分数为 450 |
| GWT-09（F09） | 玩家血量为 10，场上仍有运动实体 | 玩家被敌弹命中、血量扣为 0 | 游戏立即结束，全部实体停止运动，界面显示本局得分，并将该分数与已存最高分比较后取较大值写回 |
| GWT-10（F06） | 同一帧内 2 颗玩家子弹分别与 2 架血量为 1 的敌机重叠 | 本帧碰撞结算执行完毕 | 2 架敌机均被销毁、2 颗子弹均销毁，分数一次性增加 200，无任一碰撞对被遗漏 |

## 9. 非功能需求（全部带可测数值）

| 编号 | 类别 | 指标要求 | 验证方式 |
| -- | -- | -- | -- |
